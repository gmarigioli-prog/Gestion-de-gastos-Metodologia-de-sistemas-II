Nuestro proyecto tiene el objetivo de presentar, gestionar y analizar el historial de gastos del usuario; por lo tanto, analizamos las funciones necesarias y los patrones que se pudieran aplicar en base a eso. Actualmente, la aplicación cuenta con un frontend funcional en el que se pueden consultar y registrar datos. Aunque en este momento no hay un patrón aplicado en la página, estamos considerando la adición de un botón de undo/deshacer para casos en los que se hayan realizado registros o modificaciones erróneas. Si llegáramos a agregar esa funcionalidad, aplicaríamos el patrón Memento para implementarla, ya que está diseñado para casos en los que se busca guardar el estado previo de un objeto (como la tabla de datos en este caso) y proporciona un fácil acceso a este en caso de necesitar revertir algo. 

También estamos en proceso de construir un sistema de notificaciones por correo electrónico. Este sistema, una vez se cumplen las condiciones para enviar una notificación (como un recordatorio preestablecido, una verificación de dos pasos, un anuncio, etc.) usaría un patrón de tipo "Factory" para crear un objeto con los datos necesarios para enviar el correo y el texto a redactar en el mensaje. La factory está presenta en la build actual, pero aún no se estableció una manera de que reciba o envíe los datos necesarios.
